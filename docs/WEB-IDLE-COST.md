# 웹 대기 비용 개선 · 2026-10-06

사용하지 않는 OBS 주소를 발급해 둔 것만으로 반복 요청이 생기지는 않습니다. 하지만 이전 클라이언트가 열린 상태라면 창에서 조작하지 않아도 1초 간격으로 상태를 읽었습니다. 운영 로그에서 외부 OBS 클라이언트의 구버전 상태 조회가 약 2회/초 확인됐습니다. 이 PC의 OBS 프로세스와는 다른 연결이었습니다.

첫 개선의 Vercel 이벤트 중계도 함수 안에 실시간 연결을 유지하고 50초마다 갱신했습니다. Vercel은 CPU 실행과 별도로 진행 중인 요청의 메모리 점유 시간을 계산합니다. 기다리는 연결이라도 메모리 사용량이 발생할 수 있어 이 중계도 제거했습니다. [Vercel 함수 요금](https://vercel.com/docs/functions/usage-and-pricing)

현재는 인증된 짧은 요청으로 자기 공간의 구독 정보를 받은 뒤, 브라우저가 Upstash에 직접 알림을 연결합니다. Vercel 함수는 계속 열린 상태로 대기하지 않습니다. 정상 연결 대기 중의 주기적인 상태 조회·연결 갱신·유지용 Vercel API 호출을 제거했습니다. 실제 곡/설정 변경은 조건부 저장과 알림 발행으로 처리합니다. 네트워크가 끊긴 후에는 구독을 먼저 연결하고 최신 상태를 다시 읽습니다. 연결 중 변경은 알림 버퍼와 revision 비교로 복구합니다.

구독 키는 `ACL GENTOKEN`으로 발급하며 `ACL SETUSER`의 모든 권한·키·채널을 초기화한 뒤 자기 공간의 정확한 채널에 `SUBSCRIBE`만 허용합니다. 키 조회, 쓰기, 알림 발행, 관리자 명령, 다른 공간 구독은 허용하지 않습니다. 관리자 키는 서버에만 보관합니다. 구독 정보를 받는 API도 기존 조작/보기 키 인증이 필요합니다. [Upstash ACL 키](https://upstash.com/docs/redis/commands/server/acl-gentoken), [REST 구독](https://upstash.com/docs/redis/features/restapi)

운영자 요청으로 Redis 6개와 기존 Blob 30개 공간의 기존 OBS 키를 폐기했습니다. 곡 목록과 이미지 메타데이터는 보존했습니다. `ROOM_KEYS_REVOKED_BEFORE`로 이전 백업 키가 복원돼도 접근을 거절합니다. 구버전 revision 반복 조회는 함수 코드에서 저장소 접근 전에 410으로 거절하고, 운영 방화벽에서도 해당 요청만 함수 실행 전에 차단합니다. 이미 열린 구버전 화면은 여전히 네트워크 요청을 재시도할 수 있지만 차단된 요청은 저장소·함수에 도달하지 않습니다. Vercel은 WAF가 거절한 트래픽의 CDN 요청·전송량 비용을 면제한다고 공지했습니다. [2026년 5월 요금 변경](https://vercel.com/changelog/web-application-firewall-mitigated-traffic-is-free-on-vercel)

처음 페이지·이미지를 여는 전송, 최초 인증·상태 읽기, 실제 조작, 장애 후 재연결, 배포 빌드, 데이터 저장, Vercel 기본 구독료까지 없어지는 것은 아닙니다. Upstash도 최초 구독·재연결·변경 전송에 명령을 사용하며 요금제 한도가 적용됩니다. 단순 대기를 위해 Vercel 서버를 계속 실행하는 비용과 반복 조회를 제거한 변경입니다. 노래책은 계속 운영자가 요청할 때만 갱신합니다.

키 폐기 시에는 공간 데이터의 인증 값을 제거하고 `credentialsRevokedAt`을 기록합니다. 제한 구독 키까지 폐기하려면 해당 채널에 `room-keys-revoked`를 발행한 뒤 `kira_sub_<room ID>` ACL 사용자를 삭제합니다. 데이터는 삭제하지 않습니다. 폐기된 키를 받은 현재 클라이언트는 자동 재시도를 중단합니다.

실제 Redis와 새 브라우저 연결 시험에서 독 1개와 방송 화면 1개를 125초 동안 대기시켰을 때 추가 Vercel API 호출 0회·추가 구독 0회였습니다. 대기 직후 다음 곡 표시까지 334ms였고, 앰프 DLC 전환과 인터넷 중단 후 최신 상태 복구도 통과했습니다. 이 시험은 로컬 테스트 서버와 실제 원격 저장소를 사용했으며 3시간 OBS 방송 전체의 실측은 아닙니다. 운영 배포 결과는 별도로 확인합니다.
