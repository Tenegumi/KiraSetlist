# 보안 점검 결과 · 2026-10-05

공개 웹 버전, API, 저장소와 Git 이력, 설치형 서버 코드를 한 번 점검했어요. 실제 웹 검증은 별도로 만든 테스트 공간에서 진행했으며 사용자의 방송 리스트와 OBS 설정은 변경하지 않았어요. 전체 서비스의 안전을 인증하는 정밀 침투 테스트는 아니에요.

## 확인된 결과

| 검사 | 결과 |
| --- | --- |
| 다른 방송 공간의 키로 리스트 접근 | 403 차단 |
| 방송 화면 주소로 수정·이미지 등록·백업 | 403 차단 |
| 다른 사이트에서 조작 요청 | 403 차단 |
| 노션 예약 갱신에 인증 없이 접근 | 401 차단 |
| 제목·가수에 HTML 이벤트 삽입 | 문자가 그대로 표시되고 스크립트는 실행되지 않음 |
| 이미지 경로를 이용한 상위 폴더 접근 | 400 차단 |
| 웹의 환경 파일·개인 상태 파일 접근 | 404 차단 |
| 알려진 운영 의존성 취약점 | `npm audit --omit=dev` 결과 0건 |
| 공개 텍스트 파일·Git 이력의 비밀키 | 검사한 토큰 패턴 및 현재 서버 키 노출 없음 |

텍스트 파일 152개와 저장소에 있는 Git 이력의 텍스트 변경을 확인했어요. 비밀키 값은 보고서·로그·스크린샷에 기록하지 않았어요. 패턴 검사는 모든 종류의 비밀을 완벽하게 식별하는 검사는 아니에요.

## 이번에 보강한 부분

| 발견 사항 | 영향 | 조치 |
| --- | --- | --- |
| 익명 링크 발급에 횟수 제한 없음 | 반복 생성으로 저장소·서버 사용량 증가 가능 | Vercel 방화벽에서 IP당 60초에 5회로 제한 |
| 실제 웹 화면에 CSP 없음 | 향후 HTML 삽입 오류가 생겼을 때 방어층 부족 | 외부·인라인 스크립트, 외부 통신, 객체 삽입을 제한하는 CSP 적용 |
| 이미 파싱된 요청이 본문 크기 검사를 우회 | 의도한 입력 크기보다 큰 요청 수용 가능 | 파싱·문자열·스트림 입력 모두 검사: 일반 요청 16KiB, 이미지 요청 920,000바이트 |
| 서버 오류 원문 반환 | 내부 구현 정보 노출 가능 | 내부 오류는 일반 안내로 교체, 잘못된 JSON·배열·null은 400으로 처리 |

방화벽은 링크 발급에만 적용해요. 기존 OBS 독의 곡 추가·넘기기·화면 갱신에는 이 5회 제한을 적용하지 않아요. 실제로 잘못된 링크 발급 요청 6회를 보내 **415, 415, 415, 415, 415, 429**를 확인했고, 첫 화면은 계속 200으로 응답했어요. 이 검증은 새 공간을 생성하지 않았어요. [Vercel 방화벽과 횟수 제한 문서](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting)

CSP는 홈·독·오버레이·가이드에 적용했어요. `/demo`는 기존의 샌드박스 안에서 실행되는 정적 미리보기이며, 같은 출처 권한 없이 `allow-scripts`만 허용하는 별도의 구조예요. 본 서비스와 같은 CSP를 적용했다고 보지 않아요. 카메라·마이크·위치 권한도 실제 웹 화면에서 차단했어요.

## 남아 있는 개선 사항

- **이미지 저장 사용량 제한:** 이미지 한 장의 크기 제한은 있지만, 공간별 전체 이미지 용량·업로드 횟수 제한은 없어요. 교체한 이미지의 이전 파일도 자동 삭제하지 않아요. 악의적인 사용자의 저장소 사용량 증가를 막으려면 총량 제한과 미사용 이미지 정리가 필요해요. 이번에는 대용량 업로드 공격을 실제로 수행하지 않았어요.
- **주소 폐기·교체:** 조작 주소는 비밀번호처럼 사용하는 접근 키예요. 현재는 만료나 기존 키 폐기 기능이 없어요. 새 공간을 만들어도 예전 주소가 폐기되지는 않아요. 조작 주소를 타인에게 공유하거나 방송에 보여 주지 마세요.
- **검사 범위:** 계정 자체의 2단계 인증, 모든 클라우드 권한, OS·OBS 플러그인, 설치 프로그램의 전체 코드 서명, 대규모 분산 공격은 이번 검사 범위에 포함하지 않았어요. 로컬 서버는 코드에서 `127.0.0.1`에만 열리고 Host·Origin을 검사하는 것을 확인했어요.

검증 코드: [API·브라우저 보안 검사](../web/test/security-live.mjs), [본문 검증 테스트](../web/test/request.test.mjs), [방송 공간 권한 테스트](../web/test/rooms.test.mjs). 단위 테스트 7개가 통과했고, 실제 배포에서 권한·입력·CSP 검증이 통과했어요.
