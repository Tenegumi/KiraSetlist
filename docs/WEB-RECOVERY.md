# 웹 링크 발급 장애와 복구 · 2026-10-05

## 원인

첫 화면은 열렸지만 링크 발급과 노래책 API가 500을 반환했습니다. Vercel 로그에는 `This store has been suspended`가 기록됐으며 저장소 관리 API에서 `limits-exceeded-suspended`, `usageQuotaExceeded: true`를 확인했습니다.

기존 구현은 방송 상태를 비공개 Vercel Blob JSON 파일에 저장하고, 열린 독·오버레이·내부 디자인 프레임이 각각 1초마다 캐시를 우회해 읽었습니다. 곡을 변경하지 않아도 파일 읽기가 누적됐습니다. 이 구조가 무료 사용 한도 소진을 촉진했습니다. 어느 사용량 항목이 최초로 한도를 넘었는지는 계정의 세부 사용량으로 확인해야 합니다. HTML 출력·4K 해상도·회전 애니메이션 자체가 저장소 정지 원인은 아닙니다.

Vercel Hobby의 Blob 기본 작업 포함량은 10,000회이고 한도 초과 시 저장소에 접근할 수 없습니다. 운영자가 Vercel Pro로 변경한 뒤 기존 저장소가 `available`로 복구됐고 기존 API에서도 링크 발급이 다시 성공했습니다. [Vercel의 사용량 설명](https://vercel.com/docs/vercel-blob/usage-and-pricing)

## 바뀐 동작

- 실시간 목록·화면 설정·새 이미지 업로드는 비공개 Redis에 저장합니다. Vercel Marketplace의 Free 요금제이며 자동 유료 전환·eviction·Prod Pack은 모두 꺼져 있습니다. Vercel Pro 구독과 Redis 요금제는 별개입니다.
- 저장과 변경 알림은 조건부 쓰기 스크립트 안에서 함께 실행합니다. 다른 독이 먼저 수정했으면 409를 반환하며 최근 상태를 덮어쓰지 않습니다.
- 독과 오버레이는 인증된 이벤트 연결로 변경을 받습니다. 1초마다 상태를 읽는 요청은 제거했습니다. 디자인 프레임은 상위 화면의 연결을 공유합니다.
- 약 50초마다 연결을 갱신하고 최신 목록을 읽습니다. 알림 누락이나 재연결 중 변경이 있어도 다음 연결에서 복구합니다. 먼저 구독하고 최신 상태를 읽어 연결 초기의 변경 누락을 방지합니다.
- 서버는 15초마다 연결 유지 신호를 보냅니다. 브라우저가 35초 동안 신호를 받지 못하면 다시 연결합니다. 인터넷 연결 복구 시에는 즉시 다시 시도합니다.
- 열린 방송 화면은 연결이 끊겨도 마지막 곡을 유지합니다. 실패한 조작을 자동으로 반복하지 않습니다. 새로 여는 화면은 서버에 연결돼야 목록을 받을 수 있습니다.
- 기존 Blob의 목록과 노래책은 같은 ID·키로 Redis에 복사하며 삭제하지 않습니다. 기존 URL을 다시 발급할 필요가 없습니다. 이미 복사된 Redis 목록은 과거 Blob 목록으로 덮어쓰지 않습니다.
- 저장소 오류는 503과 안내 문구로 반환합니다. 실패한 저장소 요청은 함수 인스턴스별로 최소 60초 간격으로 재시도합니다. 노래책 조회 실패 시 마지막 목록 또는 기본 노래책을 제공하며 노래책 조회 상태를 `degraded`로 표시합니다.

## 사용량과 검증 범위

링크만 발급하고 페이지를 열지 않으면 지속적인 조회가 발생하지 않습니다. 발급 시 저장 요청과 작은 저장 공간만 필요합니다. OBS 독이나 브라우저 소스를 열어 두면 연결 갱신·초기 상태 조회가 발생합니다. 새 구조에서도 사용량이 완전히 0인 것은 아닙니다.

Free Redis에는 월 500,000명령, 256MB 저장 공간, 10GB 전송량이 포함됩니다. 명령 내부 작업·연결 수·곡 변경·업로드에 따라 실제 사용량이 달라집니다. 독 하나와 방송 화면 하나를 3시간 열어 둔 경우 연결 갱신 및 읽기만 약 1,000~2,000명령으로 계산되며 이는 실측이 아닌 예상입니다. [Upstash 요금표](https://upstash.com/pricing/redis)

검증은 실제 비공개 저장소, 공개 배포 API, 서로 다른 브라우저 프로필에서 수행했습니다. 링크 발급·기존 링크·보기 키의 조작 거절·다음 곡·디자인 전환·네트워크 끊김·자동 재연결을 확인했습니다. 3시간 연속 방송 전체를 실측한 결과는 아닙니다. 네트워크·외부 서비스 장애와 많은 동시 사용자를 포함한 운영 안정성을 보장하는 자료도 아닙니다.

공개 배포의 다섯 번 곡 전환은 클릭부터 제목 표시를 확인할 때까지 217~840ms였습니다. 자동 재연결을 반복한 뒤에는 847ms였습니다. 브라우저 자동화의 확인 간격을 포함한 측정이며 외부 인터넷·OBS 환경마다 달라집니다. 네트워크 중단 시험에서는 마지막 곡을 유지했고 인터넷 복구 후 약 313ms에 최신 곡으로 갱신했습니다. 두 창에서 정기 상태 조회는 0회였고, 두 번의 정상 갱신 주기 동안 네 개의 연결을 다시 열었습니다. JavaScript 오류와 API 5xx 응답은 없었습니다.

이미 열어 둔 독과 브라우저 소스는 한 번 새로고침해야 새 이벤트 연결 코드를 받습니다. 주소 재발급은 필요하지 않습니다.

방송 전에는 실제 OBS 독에서 곡 추가·다음 곡·원본/DLC 전환을 확인하고 **백업**을 받아 두세요. 웹은 인터넷 연결이 필요합니다. 설치형 로컬 버전은 계속 제공되며 웹과 개인 리스트는 따로 저장합니다.
