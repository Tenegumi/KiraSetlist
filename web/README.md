# 키라 웹 셋리스트

설치 없이 OBS의 사용자 지정 브라우저 독과 브라우저 소스를 연결하는 웹 버전입니다. 기존 로컬 배포는 변경하지 않습니다.

첫 화면에서 **OBS 입력할 링크 발급하기**를 누르면 조작 독 주소와 읽기 전용 방송 화면 주소가 생성됩니다. 곡 목록과 원본·앰프 DLC 선택은 비공개 Redis에 저장됩니다. 곡을 바꾸면 저장과 변경 알림을 함께 처리하고, 방송 화면은 알림을 받아 바로 갱신합니다. 초당 상태 조회는 하지 않습니다. 화면 안의 디자인 프레임은 상위 화면의 연결을 공유합니다.

연결은 서버 실행 시간에 맞춰 약 50초마다 자동 갱신합니다. 갱신할 때 최신 상태를 다시 읽어 놓친 변경을 복구합니다. 연결이 끊겨도 열린 방송 화면은 마지막으로 받은 곡을 유지합니다. 재연결 전에 누른 작업을 자동 반복하지 않습니다. 인터넷이 돌아오면 최신 저장 상태를 받습니다. 네트워크 및 서비스 장애로 조작이 잠시 멈출 수 있으므로 방송 시작 전에 곡 추가·다음 곡·디자인 전환을 한 번씩 확인해 주세요.

링크만 발급하고 페이지를 열지 않으면 정기 요청은 발생하지 않습니다. 발급 한 번의 저장 요청과 작은 저장 공간만 사용합니다. 독과 브라우저 소스를 열어 두면 변경 알림 연결과 갱신 요청이 발생합니다. OBS에서 보이지 않는 독도 열린 상태일 수 있습니다. 무료 Redis에는 명령 수·저장 공간·전송량 한도가 있으므로 사용량을 확인해야 합니다. 배포된 Redis는 Free 요금제이며 자동 유료 전환과 데이터 자동 삭제 옵션은 꺼져 있습니다. Vercel 요금제는 별도입니다.

Notion 공개 노래책은 운영자가 업데이트를 요청할 때만 수동 갱신합니다. Vercel 예약 작업은 등록하지 않으며, 사이트·독을 여는 것만으로 Notion을 가져오지 않습니다. 페이지 ID로 곡을 합쳐 새 곡·수정만 반영하고, 삭제된 곡과 기존 앨범 아트는 보존합니다. 개인 방송 공간은 변경하지 않습니다. 조회 실패·불완전한 응답은 저장하지 않아 마지막 성공 목록을 유지합니다. 이 조회는 Notion 공개 페이지의 내부 조회 API를 사용하므로 페이지 공개 설정이나 구조가 바뀌면 수정이 필요할 수 있습니다.

수동 갱신은 운영자 전용 `POST /api/sync-notion`으로 실행합니다. `NOTION_SYNC_SECRET`을 Vercel Production 환경의 비밀 값으로 설정하고, `Authorization: Bearer <운영자 비밀 값>`, `Content-Type: application/json`, 본문 `{}`을 전송합니다. 기존 배포의 `CRON_SECRET`도 호환용으로 지원하지만 예약 GET 요청은 올바른 키가 있어도 405로 거절합니다. 운영자가 요청한 경우에만 실행하며, 일반 방송 공간의 조작 키로는 갱신할 수 없습니다. 비밀 값은 브라우저·OBS 주소·공개 문서에 넣지 않습니다.

공개 `/api?op=catalog`는 수동 갱신 모드와 마지막 갱신 시각·결과를 제공합니다. 열린 독은 약 5분 간격으로 **이미 저장된 노래책**을 다시 확인할 뿐, Notion을 가져오지 않습니다. 곡 추가·다음 곡 조작의 실시간 연동은 그대로 동작합니다. 저장소를 읽지 못하면 마지막 노래책 또는 배포에 포함된 노래책을 표시하고 조회 상태를 `degraded`로 제공합니다.

배포 전에 저장소 루트에서 `npm --prefix web install`과 `npm --prefix web run build`를 실행합니다. 빌드는 기존 앱의 화면·폰트·노래책을 `web/source`에 준비합니다. 개인 상태, Node 실행 파일, OBS 설정은 업로드하지 않습니다. Vercel 프로젝트의 루트는 `web`, Node.js는 24입니다. Vercel Marketplace의 Upstash for Redis를 연결하면 `KV_REST_API_URL`과 `KV_REST_API_TOKEN`이 설정됩니다. 직접 연결할 때는 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`도 지원합니다. 서버 키는 브라우저에 제공하지 않습니다. `/api?op=health`는 실제 Redis 연결을 확인하고 실패하면 503을 반환합니다.

이전 Blob 저장소의 `BLOB_READ_WRITE_TOKEN`을 유지하면 기존 링크를 처음 열 때 같은 ID·키·목록으로 Redis에 복사합니다. 이전 데이터는 삭제하지 않고, 이미 Redis에 저장된 목록도 덮어쓰지 않습니다. 기존 이미지는 이전 저장소에서 읽을 수 있으며 신규 업로드는 Redis에 저장합니다. 이전 저장소가 정지됐다면 기존 주소의 복사는 저장소 복구 후 가능합니다.

조작용 키와 보기용 키는 URL의 fragment에 저장하며 API 인증 헤더로 전송합니다. 보기 주소로 변경·백업 요청은 거절합니다. 상태 저장은 ETag 조건부 쓰기로 충돌을 감지합니다. 웹 버전의 직접 이미지 업로드는 650KB 이하로 제한합니다.

2026-10-05 장애 원인과 재발 방지 변경은 [복구 기록](../docs/WEB-RECOVERY.md)에 정리했습니다.
