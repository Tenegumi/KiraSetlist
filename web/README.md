# 키라 웹 셋리스트

설치 없이 OBS의 사용자 지정 브라우저 독과 브라우저 소스를 연결하는 웹 버전입니다. 기존 로컬 배포는 변경하지 않습니다.

첫 화면에서 **OBS 입력할 링크 발급하기**를 누르면 조작 독 주소와 읽기 전용 방송 화면 주소가 생성됩니다. 곡 목록과 원본·앰프 DLC 선택은 비공개 Redis에 저장됩니다. 곡을 바꾸면 저장과 변경 알림을 함께 처리하고, 방송 화면은 알림을 받아 바로 갱신합니다. 초당 상태 조회는 하지 않습니다. 화면 안의 디자인 프레임은 상위 화면의 연결을 공유합니다.

변경 알림은 자기 방송 공간만 구독할 수 있는 제한된 키로 Upstash에 직접 연결합니다. Vercel 함수 안에 연결을 유지하지 않으며 50초 갱신·주기적 상태 조회·유지용 API 호출을 하지 않습니다. 연결이 실제로 끊겨 재연결할 때는 먼저 알림을 구독한 뒤 최신 상태를 읽어 놓친 변경을 복구합니다. 연결이 끊겨도 열린 방송 화면은 마지막으로 받은 곡을 유지합니다. 재연결 전에 누른 작업을 자동 반복하지 않습니다. 인터넷이 돌아오면 최신 저장 상태를 받습니다. 네트워크 및 서비스 장애로 조작이 잠시 멈출 수 있으므로 방송 시작 전에 곡 추가·다음 곡·디자인 전환을 한 번씩 확인해 주세요.

링크만 발급하고 페이지를 열지 않으면 정기 요청은 발생하지 않습니다. 발급 한 번의 저장 요청과 작은 저장 공간만 사용합니다. 독과 브라우저 소스를 처음 열 때 인증·노래책·상태를 읽고, 이후 정상 연결 대기 중에는 Vercel API를 호출하지 않습니다. 곡 변경·설정 변경·이미지 등록·백업 같은 실제 작업과 네트워크 재연결은 요청을 발생시킵니다. 페이지와 이미지의 최초 전송, 배포 빌드, 저장 공간, Vercel 구독료는 별도입니다. Upstash 알림은 최초 구독·재연결·변경 전송에 명령을 사용합니다. OBS에서 보이지 않는 독도 열린 상태일 수 있습니다. 무료 Redis에는 명령 수·저장 공간·전송량 한도가 있으므로 사용량을 확인해야 합니다. 배포된 Redis는 Free 요금제이며 자동 유료 전환과 데이터 자동 삭제 옵션은 꺼져 있습니다. Vercel 요금제는 별도입니다.

Notion 공개 노래책은 운영자가 업데이트를 요청할 때만 수동 갱신합니다. Vercel 예약 작업은 등록하지 않으며, 사이트·독을 여는 것만으로 Notion을 가져오지 않습니다. 페이지 ID로 곡을 합쳐 새 곡·수정만 반영하고, 삭제된 곡과 기존 앨범 아트는 보존합니다. 개인 방송 공간은 변경하지 않습니다. 조회 실패·불완전한 응답은 저장하지 않아 마지막 성공 목록을 유지합니다. 이 조회는 Notion 공개 페이지의 내부 조회 API를 사용하므로 페이지 공개 설정이나 구조가 바뀌면 수정이 필요할 수 있습니다.

수동 갱신은 운영자 전용 `POST /api/sync-notion`으로 실행합니다. `NOTION_SYNC_SECRET`을 Vercel Production 환경의 비밀 값으로 설정하고, `Authorization: Bearer <운영자 비밀 값>`, `Content-Type: application/json`, 본문 `{}`을 전송합니다. 기존 배포의 `CRON_SECRET`도 호환용으로 지원하지만 예약 GET 요청은 올바른 키가 있어도 405로 거절합니다. 운영자가 요청한 경우에만 실행하며, 일반 방송 공간의 조작 키로는 갱신할 수 없습니다. 비밀 값은 브라우저·OBS 주소·공개 문서에 넣지 않습니다.

공개 `/api?op=catalog`는 수동 갱신 모드와 마지막 갱신 시각·결과를 제공합니다. 노래책은 최초 로딩과 실제 변경 알림 처리 시 필요한 경우에만 **이미 저장된 노래책**을 확인합니다. 5분 캐시는 재사용 시간을 정하며 주기적인 조회 타이머가 아닙니다. Notion을 가져오지 않습니다. 곡 추가·다음 곡 조작의 실시간 연동은 그대로 동작합니다. 저장소를 읽지 못하면 마지막 노래책 또는 배포에 포함된 노래책을 표시하고 조회 상태를 `degraded`로 제공합니다.

배포 전에 저장소 루트에서 `npm --prefix web install`과 `npm --prefix web run build`를 실행합니다. 빌드는 기존 앱의 화면·폰트·노래책을 `web/source`에 준비합니다. 개인 상태, Node 실행 파일, OBS 설정은 업로드하지 않습니다. Vercel 프로젝트의 루트는 `web`, Node.js는 24입니다. Vercel Marketplace의 Upstash for Redis를 연결하면 `KV_REST_API_URL`과 `KV_REST_API_TOKEN`이 설정됩니다. 직접 연결할 때는 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`도 지원합니다. 서버 관리자 키는 브라우저에 제공하지 않습니다. 신규 방송 공간은 `ACL GENTOKEN`·`ACL SETUSER`로 하나의 정확한 채널에 `SUBSCRIBE`만 허용한 사용자와 제한된 키를 만듭니다. 키 조회·쓰기·발행·다른 공간 구독은 불가능합니다. `/api?op=connection`은 기존 조작/보기 키 인증 후 이 제한된 구독 키만 반환합니다. CSP는 HTTPS Upstash 연결을 허용합니다. `/api?op=health`는 실제 Redis 연결을 확인하고 실패하면 503을 반환합니다.

이전 Blob 저장소의 `BLOB_READ_WRITE_TOKEN`을 유지하면 기존 링크를 처음 열 때 같은 ID·키·목록으로 Redis에 복사합니다. 이전 데이터는 삭제하지 않고, 이미 Redis에 저장된 목록도 덮어쓰지 않습니다. 기존 이미지는 이전 저장소에서 읽을 수 있으며 신규 업로드는 Redis에 저장합니다. 이전 저장소가 정지됐다면 기존 주소의 복사는 저장소 복구 후 가능합니다.

조작용 키와 보기용 키는 URL의 fragment에 저장하며 API 인증 헤더로 전송합니다. 보기 주소로 변경·백업 요청은 거절합니다. 상태 저장은 ETag 조건부 쓰기로 충돌을 감지합니다. 웹 버전의 직접 이미지 업로드는 650KB 이하로 제한합니다.

기존에 발급된 모든 OBS 키는 운영자 요청으로 폐기했습니다. 저장된 곡 목록과 이미지 데이터는 보존하지만 이전 주소로 접근할 수 없습니다. 첫 화면에서 새 링크를 발급해 사용해 주세요. 폐기된 키와 함께 `ROOM_KEYS_REVOKED_BEFORE` 시각 이전의 백업 키도 거절합니다. 구버전의 `revision` 반복 조회는 저장소에 접근하기 전에 410으로 종료하며, 새 화면은 인증 오류를 받으면 재시도를 멈춥니다. 이전 Vercel 중계 이벤트 연결도 410으로 종료합니다. 운영 배포에는 구버전 revision 조회를 함수 실행 전 방화벽에서 차단하는 규칙도 적용합니다. 이미 열린 구버전 화면은 새로고침하거나 닫아야 그 화면의 요청 자체가 중단됩니다. 키 폐기 시 공간의 `kira_sub_<room ID>` ACL 사용자도 삭제하고, 삭제 직전에 `room-keys-revoked`를 해당 채널에 발행해 열린 새 화면을 종료해야 합니다.
